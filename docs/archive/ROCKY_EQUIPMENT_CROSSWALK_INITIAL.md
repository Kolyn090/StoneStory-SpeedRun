## Controlled in-game procedure

1. Open the private `TEST_PLAN.md`. If the isolated diagnostic is absent, install it using the **existing** `tools/Install-SelectorValidation.ps1` and its recorded original candidate directory, following `EQUIPMENT_SELECTOR_VALIDATION.md`. The installer defaults to count-only and backs up any existing diagnostic namespace. It touches `EquipmentSelectorTest` only. Use the same files in both known Stonescript roots if both are maintained; do not install B2.1/R1 or overwrite Mind Stone text through tooling.
2. Save the full current Mind Stone text and loadout in a local note. In-game, temporarily use **only** `import EquipmentSelectorTest/main`. Start a fresh safe Rocky Plateau run at a recorded difficulty, supervised. The overlay must say `Allow equip: false`. No new equipment request should be sent by the validator. This is an identity test, not a completion run.
3. Count the nine first-pass cases listed privately: Fire Sword broad/+21; Compound Shield broad/+21/shiny; Vigor Shield broad/+21; Heavy Hammer broad/+21. Left/Right browse, Down recounts. Index is case number minus one. Record the actual displayed query and count, including zero or unexpected counts. Source-associated record counts are not expected runtime counts. A native error is different from a zero match; capture Tab's file/line/message.
4. Only after count-only behavior is correct, back up the installed diagnostic `main.txt` in each root. In those diagnostic copies only, change `var allowEquip = false` to `true`. Keep repository source false. Start a fresh run and confirm the overlay. Select a positive-count case, press **Up**, release it, then press **Enter once**. Browsing/recounting cancels arming. The module sends a single equipment request and does not activate abilities. Native combat and equipped passive effects can still occur.
5. Test Fire Sword, then a narrowed Compound Shield query, then Vigor Shield, then Heavy Hammer. Inspect equipped details and both hands after each request. Fire Sword must show the 0055 profile; the desired Compound candidate must match 0010 rather than the basic duplicate; record **which** Vigor variant appeared. Heavy Hammer must show 0061, and its actual hand occupancy must be recorded. A query with multiple matches remains ambiguously targetable even if it happens to select the desired item once. The next-frame text is diagnostic evidence, not a complete item-instance identifier.
6. Optional second pass: Ice Shield broad/+21/shiny, Fire Hammer non-heavy broad/+21, then alternative swords. For Fire Hammer test the one-handed request with the already confirmed shield present, recording whether the shield stays equipped. Do not infer that retained shield behavior is proven from query hand metadata. Bashing/Towering optional identity tests may follow; keep Dashing count-only initially. Do not activate Heavy Hammer, Bashing Shield or any other ability during identity validation.
7. Stop on native errors, wrong equipment, unexpected movement or ambiguous details. Record the last query, action and both hands. Mark blocked/ambiguous, not pass. Leave the run or disable Mind Stone if needed; this validator provides no survival automation.
8. Back up the test diagnostic copies, restore `allowEquip = false`, and restore the saved Mind Stone text/loadout. Confirm original automation/observer behavior separately. Preserve installer backups; if needed restore only the recorded pre-test diagnostic namespace, leaving unrelated scripts intact. Do not promote any Rocky completion or combat strategy from these tests.

Report build, difficulty, case/index/query, count, command hand, live/next-frame L/R, displayed stars, both enchantments, base stats, conditional effects, screenshot ID matched, native errors and any unexpected switching/movement. Report whether **exact details match**, **a different known variant was selected**, or **identity remains ambiguous**. Share cropped item/diagnostic evidence without player/account/save identifiers. Keep full source pointers and raw enchantment structures in the private result file.
